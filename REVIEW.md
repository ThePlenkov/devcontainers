# Review Rules and Lessons

Generic review rules for this repository, derived from real review cycles.
Apply these to every feature and PR.

## Security Rules

1. **Never write API keys to `/etc/environment`.** Credentials must be injected
   at runtime via env vars or secrets, not persisted in image layers.

2. **Verify downloaded binaries with SHA-256.** Download `checksums.txt` from
   the release, extract the expected hash for the target artifact, compute the
   downloaded file's SHA-256, and abort on mismatch. If checksums are
   unavailable, warn explicitly — do not silently skip.

3. **Enforce HTTPS on all curl downloads.** Use `--proto =https` and
   `--proto-redir =https` to prevent HTTPS-to-HTTP downgrade redirects.

4. **Download-then-execute, never `curl|bash`.** Download installer scripts to
   a `mktemp -d` directory, then execute the local copy. Use `trap` for cleanup.

5. **Use `--ignore-scripts` on `npm install -g`.** Run `npm rebuild -g <pkg>`
   after install to explicitly execute postinstall for packages that need it
   (native binaries, plugin hotfixes). This satisfies SonarCloud S6505 while
   preserving functional correctness.

## Robustness Rules

6. **Never use `$HOME` in profile.d scripts.** OpenShift restricted SCCs can
   set `HOME=/`. Use fixed fallback paths like `/home/vscode/...` instead.

7. **Use `ln -sf`, not `cp`, for npm-installed binaries.** Copying
   dereferences npm's symlink, breaking package tree resolution. Always
   symlink to preserve the npm install location.

8. **Resolve npm binaries from `$NPM_GLOBAL_BIN`, not `command -v`.** Using
   `command -v` can pick up pre-existing PATH entries. Resolve from
   `$(npm bin -g)` or `$(npm config get prefix)/bin`.

9. **Do not suppress symlink creation errors.** Remove `|| true` and
   `2>/dev/null` from `ln -s` commands so failures are visible. Non-critical
   `chown` fallback suppression is acceptable.

10. **Use `[[ ... ]]` for shell tests.** Safer and more feature-rich than
    `[ ... ]`. Exception: profile.d content sourced by POSIX shells must use
    `[ ... ]`.

11. **Guard against self-link.** When an installer may already place a binary
    in `/usr/local/bin`, guard the `ln -sf` with:
    `if [[ -n "$BIN" && "$BIN" != "/usr/local/bin/X" ]]; then ln -sf ...`

12. **Fail on missing checksums.** Do not use `|| true` on checksum download.
    If checksums are unavailable, fail the build rather than installing
    unverified artifacts.

13. **Pass `VERSION` to installers.** When a feature has a `VERSION` option,
    pass it to the upstream installer for pinned installs. Only omit it for
    `latest`.

14. **Install system-wide for non-root access.** Use `UV_INSTALL_DIR=/usr/local`
    or equivalent so tools are accessible to all users, not just root.

## Convention Rules

15. **Add Node to `dependsOn`** for all npm-based features:
    `"ghcr.io/devcontainers/features/node": {}`

16. **Bump major version on breaking changes.** When default behavior changes
    (e.g., `shareConfig` from always-on to opt-in), bump to `2.0.0`.

17. **`shareConfig` is opt-in.** Default `false`. When `true`, symlink the
    native config path to `${AGENT_CONFIG_DIR}/<id>`. Every feature managing
    a config directory SHOULD have this option. Runtimes and build tools that
    don't manage agent configuration are exempt.

18. **Do not hand-edit README files.** They are auto-generated by the release
    workflow.

19. **Use `jq` for JSON parsing** with a grep/cut fallback for environments
    without jq.

## Rejected Findings (Precedent)

These findings were rejected with documented reasons. Cite this section when
the same pattern is flagged again.

### Upstream installer scripts without SHA-256 (coderabbit, cubic)

**Pattern:** Hermes and Grok installers do not publish SHA-256 checksums for
their install scripts.
**Reason:** This is the official distribution method. We mitigate with
download-then-execute over HTTPS (`--proto =https --proto-redir =https`).
The downloaded script can be inspected before execution. No upstream
checksum exists to verify against.

### Runtime sed patching of upstream JS (codacy HIGH RISK)

**Pattern:** openshift-compat patches Paseo's `web-ui.js` via `sed` at
runtime to fix a missing default port in Host header behind reverse proxies.
**Reason:** The patch operates on a COPY (not the original), uses a custom
ESM loader to intercept imports, is guarded by `grep` to prevent
double-patching, and is wrapped in `set +e` with `|| true`. This is the
only way to fix the upstream bug without forking. An env var override is
not possible because upstream doesn't expose one.

### README documentation updates (cubic P3)

**Pattern:** README still documents old behavior (copied binary, old version
tag) after install.sh changes.
**Reason:** README files are auto-generated by the release workflow. They
will be regenerated on release. Hand-editing is prohibited by repo convention.
